# 分镜与画面制作：五条悟（Gojo）示例

## 历史方案的可重用部分

此前合作版曾沿着这些版本迭代：V8/V9 输出横屏、竖屏；V9 采用真实聊天内容滚动、点击 Codex 图标、蓝色粒子/能量环、五条悟逐渐显现、收起侧栏的主题界面；后续针对左侧不美观的马赛克制作了无马赛克返工版。示例工程包含 `assets/`、`projects/`、`exports/` 等结构；最终无马赛克视频属于该机器上的历史文件，**此 Skill 包不包含该视频，也未验证其内容**。

V9 后段曾采用历史主题截图/素材，因此即使视觉上像 Codex，也不能仅据它推定当时真实 Codex 已同步更新到相同状态。设计新作品时，最后只承诺启动真实应用，不用旧截图作为“现状证明”。

## 推荐 10 秒脚本（参考而非强制）

| 时间 | 内容 | 处理重点 |
|---|---|---|
| 0.0–1.8s | 暗色代码/聊天片段快速滚动 | 演示内容必须无隐私；侧栏默认折叠 |
| 1.8–3.0s | 画面中央 Codex 标志出现/被点击 | 鼠标动作自然，点击与音效同步 |
| 3.0–4.6s | 冰蓝能量从图标向外爆发 | 细粒子、环状折射、避免闪烁过强 |
| 4.6–7.5s | 五条悟风格人物与六眼能量意象显现 | 不依赖原作片段；可以改用原创角色 |
| 7.5–9.2s | 能量回收成流光、背景深蓝色 | 预留黑底/深色亮度一致的结尾 |
| 9.2–10.0s | 快速淡出动画，启动真实 Codex | 不冒充真实程序界面截图 |

可按用户指定修改；与 Codex 真正打开时间可能有差距，需在实机优化。成片建议 H.264 MP4、yuv420p、统一帧率，避免播放端解码问题；需竖版时逐镜重新构图而非简单横屏裁切。

## 生成提示词模板（交给可用的图像/视频模型）

静态首帧画面：
> 深蓝黑现代科技场景，主题为无限空间与冰蓝能量，画面中保留中央负空间以承载 Codex 标志，蓝白色微弱能量环围绕中心，粒子层次丰富，画面清晰、电影感、无水印、无文字、无真实用户数据，16:9。

转场视频：
> 10 秒动漫主题软件启动片段，0–2 秒暗色抽象聊天界面滚动，2–3 秒点击中心程序图标，3–6 秒冰蓝色能量环与粒子向四周扩散，6–8 秒动漫角色意象和无限空间折射逐渐浮现，8–10 秒粒子收束并淡出成深蓝黑。保持画面中心与主角一致，动画流畅，特效不过曝，不闪烁，不展示真实隐私文字，不使用原作动画镜头。

转场剪辑：
- 场景连接用真实能量运动方向，不要仅把几个图叠加做生硬交叉溶解。
- 按音效节点（点击、扩散、能量收束）对齐画面事件，背景音乐按用户需求决定，勿默认自动加歌。
- 首屏侧栏意外展开 → 从录制源修改 UI 状态并重录，不能简单打马赛克。
- 逐段检查，优先局部返工；限制无意义的重复生成消耗。

## 工程目录建议

```text
Codex_Anime_Startup/
  assets/               # 用户有权使用的插画、音效、icon、演示素材
  projects/             # 剪辑/合成工程与提示词
  exports/              # intro.mp4、横版/竖版成片
  launcher/             # PowerShell 启动器副本（脚本安装时创建）
  shortcuts/            # 新动画快捷方式
  backup/               # 原始 Codex 快捷方式
```

除用户指定的示例目录以外，其他电脑优先把工程放到 Documents 或明确指定的项目盘。项目文件不放桌面；可选桌面快捷方式仅是 `.lnk`，不是项目素材。
