# V13 音轨方法：不吵的真实操作 → 安静转场 → 动漫登场渐强

## 为什么不用整条歌从头铺到尾

影片的关注点从真实输入、滚动过渡转向动漫人物登场。开头如果从聊天记录就放高音量歌曲，会减弱后半段的情绪差值，让视频看上去很吵。更合理的声画因果：哪个物体在动就听到对应动作；出现角色才让音乐响起。

## 必须遵循的阶段

1. `typing_end` 前按真实画面中打字出现频率布置键盘敲击。不要机械地每秒固定 N 次。
2. `scroll_start`–`scroll_end` 只在**有滚动视觉变化**时布置 `scroll_times`。静止时不发声；无背景歌。用户说“看不到音效”，通常是滚轮声响度不足或事件落在错误的时间点。
3. `icon_start`–`reveal_start` 无歌曲；可以有轻微图标出现、鼠标点击或非常轻的动效声；不要叠加过强的旧能量冲击声。
4. `reveal_start` 才开始用户提供的有权使用的歌曲。由 `music.song_offset_seconds` 决定选用曲目的起始位置；`start_gain` 是低音量基底，`rise_gain` 在 `rise_seconds` 内渐入。
5. `theme_start` 开始 `outro_seconds` 淡出。如果长度短、画面完成更早，必须重新定义收尾点。

## 脚本设计

`generate_sound_effects.py` 用本地合成的简短键盘/滚轮/点击音生成**与整条视频同长度**的 WAV；这不是商用音源采样，需与画面核对，不保证比真实录制音更逼真。用户有自己的真实键盘/滚轮录音时，优先替换合成音效并保持分段无歌原则。

`sync_music.py` 以视频为画面源，却**不取其原始音频**。最终音轨只包含传入的 WAV 与指定曲目。音频在 `reveal_start` 按毫秒延迟，低音量基底先入，主体由弱到强，`theme_start` 后渐出。输出视频流直接复制，理论上画面完全一致；使用 `verify_output.py --compare-video-to` 对比封装后的实际视频流哈希。

## 22.208 秒实例

- 音轨时轴：0–2.39 键盘；2.39–7.625 滚动（约 4.40–7.49 实际出现滚轮声）；7.625–10.625 轻微转场，不要音乐。
- 10.625s 歌曲开始。用户案例将曲目起点设为第 55 秒，`start_gain=0.09`；第二层主体音量 `rise_gain=0.65`，渐强 7.35 秒。
- 19.375s 开始约 2.833 秒的收尾淡出，最终 22.208s 结束。
- 版本 V10、V11、V12 以及前面的 A/B 均保留，不要覆盖。

## 如何判断声音是否合适

- 明确听到滚动声，但不能像打字声那样抢戏。
- 图标段只听得到轻微动作，没有歌曲节奏。
- 音乐登场初期不突然爆音，中间逐渐增强，到角色完整显现时最大，进入 Codex 界面淡出。
- 以实际设备试听为准。`volumedetect` 的平均/峰值指标只能诊断相对变化，不能自动证明歌曲“恰好符合视觉节拍”。
